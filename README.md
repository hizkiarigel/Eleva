# Eleva — Web MVP (Beta)

AI Character Growth System. Alur: Daftar (kode beta) → Onboarding → AI Analysis → Daily Quest → Reflection → Dashboard.

Beta gratis, pilot tertutup 10 orang terundang selama 14 hari lewat kode undangan (`BETA_CODE`) — bukan pendaftaran terbuka. Postgres (multi-user), Express backend, vanilla JS frontend. Tanpa build step. Model AI: Claude Sonnet (bukan Haiku — kualitas "mentor voice" adalah validasi utama pilot ini, biayanya jauh di bawah budget di skala 10 orang).

**Belum ada pembayaran/billing** — beta ini gratis sampai periode betanya selesai. Jangan diasumsikan ada monetisasi aktif.

## Jalanin di lokal

Butuh Postgres lokal (`createdb eleva_dev` atau setara).

```bash
npm install
cp .env.example .env
# isi ANTHROPIC_API_KEY, DATABASE_URL, BETA_CODE, SESSION_SECRET di .env — lihat komentar di .env.example
npm start
```

Buka `http://localhost:3000`. Tanpa akun, kamu akan diarahkan ke layar daftar/masuk — daftar butuh `BETA_CODE` yang cocok dengan env var-nya.

Tanpa `ANTHROPIC_API_KEY`, aplikasi tetap jalan — quest jadi generik (fallback), dan refleksi tidak menaikkan stat. Ini disengaja: tidak ada AI mentor sungguhan, tidak ada growth palsu.

## Struktur

```
server/
  index.js    → Express app + routes, semua route app di belakang auth middleware
  auth.js     → signup/login (bcrypt + BETA_CODE), dipanggil dari index.js
  db.js       → Postgres (pg), semua query di-scope per user_id
  claude.js   → panggilan ke Claude API + fallback kalau key belum ada / gagal
  safety.js   → deteksi frasa krisis, independen dari AI (lihat bagian Prinsip di bawah)
public/
  index.html, styles.css, app.js  → frontend vanilla JS, termasuk layar auth + privacy notice
reference/
  Eleva_Prototype.jsx              → prototype React yang jadi acuan fitur Pathway (bukan bagian dari app produksi)
  Eleva_Correlation_Matrix.html    → peta bukti riset 21 pasangan sinergi radar (buka di browser, tap sel untuk sitasi)
  ELEVA_Constitution_Product_Bible_v1.9.docx → filosofi produk & changelog keputusan (v1.5 = 7 elemen MECE; v1.6-v1.7 = rename+reframe Pathway; v1.8 = gate kespesifikan; v1.9 = input terstruktur quest fisik + roadmap Capacitor; menggantikan v1.7 yang di-commit sebelumnya)
```

## Auth & multi-tenant

- Email + password (di-hash pakai bcrypt), session lewat cookie httpOnly yang di-sign (`cookie-session`, secret dari `SESSION_SECRET`). Tidak ada magic link/OAuth, tidak ada flow lupa password — sengaja sederhana untuk beta terkontrol.
- Signup wajib isi `BETA_CODE` yang cocok dengan env var — cara paling sederhana buat batasi kecepatan pertumbuhan (dan biaya API) selama beta.
- Semua route data (`/api/state`, `/api/profile`, `/api/reflection`, `/api/reset`) ada di belakang middleware auth dan **selalu discope dari `req.userId` (session), bukan dari body/param request** — supaya user tidak bisa akses/ubah data user lain walau coba manipulasi request API langsung.
- Privacy notice singkat (bukan kebijakan privasi hukum formal) ditampilkan di layar daftar, wajib dicentang sebelum tombol daftar aktif.

## Prinsip desain yang tertanam di kode (bukan cuma di dokumen)

- **Growth butuh substansi — tiga lapis anti-Goodhart** (Bible bab 11): (1) gate deterministik `wordCount` di `server/index.js` — refleksi di bawah ~12 kata tidak pernah menaikkan stat; (2) **gate kespesifikan** (sejak v15/Bible v1.8, di prompt `processReflection`): kalau deskripsi quest eksplisit meminta detail konkret (angka/ukuran/observasi), refleksi generik yang tidak menyebut satu pun detail itu ditolak growth-nya BERAPA PUN panjangnya — refleksi singkat-tapi-spesifik justru sah, dan quest kualitatif yang tidak minta angka tidak dipaksakan standar angka; (3) **input terstruktur untuk quest fisik** (sejak v15/Bible v1.9): quest fisik diselesaikan lewat field angka (jenis/durasi/jarak/RPE/titik berat, atau gerakan/set×rep/beban) yang kelengkapan & kewajarannya divalidasi kode (`server/structured.js` — kombinasi mustahil seperti "lari 15 km dalam 20 menit" ditolak dengan pesan jelas), refleksi naratif jadi opsional, dan angkanya jadi baseline progresif untuk quest berikutnya ("minggu lalu 15 repetisi, sekarang coba 18"). **Revisi founder (10 Agustus, dari melihat quest fisik lawas yang cuma dapat kotak refleksi teks): JENIS record dipilih PENGGUNA saat menyelesaikan, bukan ditebak AI saat generate.** Tombol quest sekarang "Mulai" (bukan "Tandai & refleksi"); untuk quest fisik muncul picker "Aktivitasnya jenis apa?" — **Cardio / Gym tanpa alat / Gym dengan alat** — dan form record-lite mengikuti pilihan itu (dua varian gym memakai validasi `gym` yang sama, bedanya cuma field beban disembunyikan untuk bodyweight; beban sisa dari gonta-ganti varian tidak pernah ikut terkirim). Alasannya: quest fisik sering terbuka soal aktivitasnya ("push-up, jalan cepat, atau latihan apapun") — satu `structuredKind` pre-baked tidak mungkin tahu yang benar-benar dikerjakan. Tag AI (`completionType`) sekarang cuma menentukan bahwa record itu WAJIB (tetap ditegakkan server); `kind` yang divalidasi diambil dari payload pengguna (fallback ke tag lama untuk kompatibilitas). Quest non-fisik tetap form teks, tapi ada link "Aktivitas fisik? Catat sebagai record →" untuk opt-in ke picker yang sama — sekaligus jalur untuk quest fisik lawas dari era sebelum tagging (kasus persis yang founder alami). Bug nyata yang ketemu saat verifikasi browser (lolos syntax check & curl, cuma ketahuan lewat intercept POST body): tombol picker memakai class styling `.status-btn` yang sama dengan baris status, dan handler status yang lama di-bind per-CLASS — jadi tap tombol jenis ikut menjalankan handler status dan mengosongkan `reflectStatus` diam-diam (payload terkirim tanpa `status`, record tersimpan kosong). Fix: handler status di-bind per-atribut `[data-status]`, bukan per-class.
- **Riwayat jujur soal hari yang terlewat** (bug dilaporkan founder di produksi, 10 Agustus): dashboard sempat menampilkan hari yang TIDAK pernah direfleksikan sebagai entri polos di bawah "RIWAYAT" — bedanya cuma warna border tipis, gampang terbaca sekilas di layar HP seolah sudah tercatat/selesai padahal belum dikerjakan sama sekali. `allHistory` (`server/db.js`) memang sengaja mengembalikan SEMUA hari lampau termasuk yang `reflection`-nya masih null — menyembunyikan hari terlewat dari riwayat justru bentuk lain dari menyamarkan progres, bukan lebih jujur. Perbaikannya di lapisan tampilan (`public/app.js`+`styles.css`): entri tanpa refleksi sekarang dapat class `.missed` (border rust, redup) plus label eksplisit "Terlewat — belum dikerjakan", kontras jelas dari entri selesai (border hijau + cuplikan refleksi asli). Susulan founder di hari yang sama: hari terlewat juga harus tetap terlihat langsung di area QUEST HARI INI, bukan cuma di Riwayat yang perlu discroll — `.quest-carousel` (pola scroll-snap yang sama dengan Pathway carousel v7) menaruh kartu hari ini sebagai slide pertama diikuti kartu-kartu hari terlewat (awalnya read-only tanpa tombol aksi — direvisi lagi hari yang sama, lihat butir refleksi retroaktif di bawah), digeser lewat swipe horizontal; caption kecil di bawah carousel menghitung berapa yang terlewat. Carousel otomatis kembali ke kartu tunggal (tanpa swipe) begitu pengguna mulai mengisi refleksi hari ini, supaya gestur geser horizontal tidak berebut sentuhan dengan mengetik di form.
- **Quest hidup 24 jam rolling dari saat diterbitkan, bukan sampai tengah malam lokal** (susulan ketiga founder di hari yang sama, dari akar masalah yang sama seperti dua butir di atas): sebelumnya quest "hari ini" ditentukan murni dari tanggal kalender (`todayKey()`) — quest yang diterbitkan jam 11 malam otomatis jadi "kemarin" begitu jam berganti tanggal, walau umurnya belum genap sejam, lalu nongol di Riwayat seolah terlewat padahal user belum sempat. Diganti total: `days.issued_at` (TIMESTAMPTZ, kolom baru) jadi sumber kebenaran, `getActiveDay` (`server/db.js`) mengembalikan baris DENGAN `issued_at` PALING BARU milik user itu (bukan yang cocok tanggal hari ini), dan `active` dihitung `issued_at + 24 jam > sekarang` — quest yang sama tetap satu-satunya "quest hari ini" yang bisa dikerjakan sampai genap 24 jam sejak diterbitkan, apa pun yang terjadi ke tanggal kalender di antaranya. Countdown ⏳ HH:MM:SS hidup di `public/app.js` (`startCountdown`, tick tiap detik via `setInterval`, langsung tulis ke DOM node — sengaja TIDAK lewat `renderDashboard()` supaya draft refleksi yang lagi diketik di tempat lain tidak keganggu), berubah warna rust di bawah 1 jam tersisa, dan otomatis `boot()` ulang begitu bener-bener habis. **Batas 24 jam ini murni soal KAPAN quest baru diterbitkan** (pacing satu quest per hari-rolling) — soal APAKAH quest lama masih bisa diselesaikan setelah lewat waktu itu direvisi total di butir refleksi retroaktif di bawah, di hari yang sama. `upsertDay` lama dipecah jadi dua fungsi jujur secara semantik: `createQuest` (SELALU menerbitkan `issued_at = now()` yang baru, bahkan kalau kebetulan tabrakan `(user_id, date)` dengan baris lama — baris lama itu HANYA baris yang levelnya benar-benar expired, jadi digantikan penuh, bukan sekadar ditimpa reflection-nya) dan `saveReflection` (murni menempel refleksi, sengaja TIDAK menyentuh `issued_at` — supaya menyelesaikan quest lebih awal tidak mereset jatah 24 jam quest berikutnya). Bug nyata yang ketemu & diperbaiki saat testing manual (bukan cuma teoretis): early draft `upsertDay` mempertahankan `issued_at` lama pada `DO UPDATE`, yang dalam skenario buatan (bukan pemakaian asli — di dunia nyata regenerasi quest cuma terjadi setelah ≥24 jam sungguhan berlalu, yang selalu mendorong tanggal kalender maju melewati tanggal baris lama) bisa bikin quest baru mewarisi jam kedaluwarsa quest lama dan langsung dianggap expired lagi → `boot()` re-fetch tanpa henti. Migrasi kolom `issued_at NOT NULL DEFAULT now()` membackfill baris lama dengan SATU timestamp yang sama (waktu migrasi jalan) — `getActiveDay` memakai `date DESC` sebagai tiebreak supaya baris terbaru di antara mereka tetap benar terpilih.
- **Quest yang terlewat tetap bisa direfleksikan kapan pun, bukan cuma dilihat** (susulan keempat founder di hari yang sama, setelah lihat versi read-only-nya live: "tolong ini dibuka lagi"): kartu terlewat di `.quest-carousel` sekarang punya tombol "Tandai & refleksi" sungguhan (`data-reflect-date`, bukan `id` unik seperti tombol hari ini karena bisa ada beberapa kartu terlewat sekaligus), yang membuka form refleksi YANG SAMA PERSIS dengan hari ini — gate kespesifikan, gate 12-kata, dan validasi input terstruktur semuanya berlaku identik, jadi keterlambatan tidak pernah melonggarkan apa yang dianggap "nyata". ## Prompt caching

`server/claude.js`'s system prompt (`MENTOR_SYSTEM`, sama persis di setiap panggilan onboarding maupun harian) pakai `cache_control` Anthropic supaya panggilan berulang dalam window cache lebih murah. Catatan jujur: system prompt saat ini diperkirakan masih di bawah ambang minimum 1024 token yang dibutuhkan model (`claude-sonnet-4-6`) supaya benar-benar ke-cache — kodenya sudah terpasang (tidak ada biaya tambahan kalau belum ke-cache), tapi cache hit belum terverifikasi jalan nyata. Cek `cache_read_input_tokens` di log (`[claude usage] ...`) begitu jalan di production dengan API key aktif.
